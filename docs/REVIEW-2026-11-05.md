# Revue autonome du 5 novembre 2026

Revue croisée par trois agents (données/édition, UX, scène), puis inspection du site de production `https://mybob-9rj.pages.dev/` dans un vrai navigateur à 1280 × 720. Source locale initiale : e940b66. Aucun correctif produit ni déploiement effectué.

Mise à jour après autorisation de correction : les dix défauts ci-dessous sont traités dans le code local, ainsi que la confirmation avant remplacement d’un projet importé. Voir `HANDOFF.md` pour la validation finale et les limites. La suite de ce document conserve les constats initiaux.

## Constats prioritaires

### 1. P2 — Changer la forme d’un canapé utilise une profondeur incorrecte

Source : `src/furniture/panel.ts:396`.

Reproduit en production : ajouter le canapé standard, ouvrir Modifier, passer de Droit à Angle, conserver corps 90 cm / total 180 cm / retour 90 cm, Enregistrer. Une erreur affirme que la profondeur totale ne dépasse pas celle du corps. Ces mesures sont pourtant valides. Le code restaure `item.depth` quand les champs de profondeur sont inchangés, sans prendre en compte la nouvelle forme. Dans l’autre sens, angle vers droit conserve la profondeur totale au lieu de celle du corps (reproduction exécutée sur la méthode réelle avec champs factices).

Correction : tenir compte du changement de forme dans la préservation des valeurs exactes. Couvrir les deux sens et Annuler.

### 2. P2 — La minicarte masque des commandes sur un écran de portable

Sources : `src/style.css:827` et règles `.mini-card`.

Confirmé visuellement à 1280 × 720 en Vue 3D, Plan et entrée Visite : la minicarte recouvre le bas de la colonne des outils, notamment Recentrer et une partie de Plafond. Les deux blocs partagent le côté droit et leur hauteur ne s’adapte pas à l’espace disponible. La minicarte disparaît seulement sous 600 px de hauteur.

Correction : réserver des zones distinctes ou réduire/replier la minicarte lorsque la hauteur disponible ne suffit pas. Vérifier aussi 1366 × 768, zoom navigateur 125 %, et barre latérale masquée.

### 3. P2 — Des modifications non sauvegardées peuvent être perdues lors d’un changement de projet/niveau

Sources : `src/main.ts:124`, `src/main.ts:228`.

Constat de code : si `localStorage.setItem` échoue, les meubles modifiés restent dans l’historique en mémoire et le statut devient Non sauvegardé. Changer de projet ou niveau recharge ensuite le stockage et réinitialise cet historique sans préserver cet état. Scénario à tester par injection d’une erreur de quota ; pas de saturation volontaire du navigateur utilisateur.

Correction : conserver les états non sauvegardés par projet/niveau, ou proposer export et annulation du changement avant de les abandonner.

### 4. P2 — La date et l’heure solaires ne survivent pas à l’export ou au rechargement

Sources : `src/ui/solarPanel.ts:19`, `src/ui/solarPanel.ts:123`, `src/main.ts:710`.

Constat de code : l’instant choisi reste en mémoire ; seules localisation, orientation, fuseau et étiquette sont sauvegardés/exportés. Recharger ou importer le projet utilise un autre instant et produit un autre soleil. Cela empêche de reproduire une étude d’ensoleillement. L’instant est aussi partagé entre les projets dans la session.

Correction : inclure l’instant choisi dans les préférences et le format exporté, avec compatibilité des anciens fichiers, ou annoncer explicitement son caractère temporaire.

### 5. P2 — Entrée dans Commune peut associer une nouvelle ville aux anciennes coordonnées

Sources : `src/ui/solarPanel.ts:48`, `src/ui/solarPanel.ts:90`, `src/ui/solarPanel.ts:123`.

Constat de code : Rechercher est un bouton non submit ; Entrée soumet le formulaire à Appliquer. Avec une localisation déjà valide, remplacer le nom de commune puis Entrée peut enregistrer cette nouvelle étiquette avec les anciennes coordonnées, cachées dans les détails.

Correction : Entrée dans Commune doit lancer la recherche ; distinguer le texte recherché de la localisation effectivement sélectionnée.

### 6. P2 — Un plafond visible ne projette pas d’ombre solaire en Visite

Sources : `src/scene/viewer.ts:307`, `src/scene/buildHouse.ts:511`, `src/scene/viewer.ts:641`.

Constat de code, effet solaire non reproduit visuellement : Visite désactive les toits ; le plafond visible n’est pas ajouté aux objets projetant des ombres. Une couverture visible peut donc laisser passer le soleil dans le rendu. Cela dépasse les approximations météo/voisinage annoncées.

Correction : conserver une couverture occultante dans la passe d’ombres de la visite et vérifier une pièce fermée au soleil haut.

### 7. P2 — Les pièces abaissées autres que le garage ont des ouvertures extérieures incohérentes

Sources : `src/scene/buildExterior.ts:166`, `src/scene/buildHouse.ts:78`.

Constat de code : la structure intérieure utilise `floorOffset` pour toutes les pièces ; les façades ne le prennent en compte que pour le garage. Un séjour ou une chambre abaissée importée peut avoir une ouverture intérieure et une façade à des hauteurs différentes.

Correction : mutualiser le calcul d’altitude des ouvertures. Ajouter un projet générique de test avec séjour abaissé et fenêtre extérieure.

### 8. P2 — L’import accepte certains contours auto-intersectants

Source : `src/model/validate.ts:136` et validation des contours de niveaux/pièces.

Reproduit avec le validateur réel : contour `[[0,0],[6,6],[0,6],[4,0]]`, départ `[2,5]`, pièces/murs/lumières vides. Le projet est accepté avec aire 6 m² malgré le croisement. La validation de polygone simple existe déjà pour les terrains et toitures. L’impact graphique exact reste à tester.

Correction : rejeter les contours croisés des niveaux et pièces avant triangulation et calcul de surface.

### 9. P3 — Déverrouiller nécessite de fermer puis rouvrir l’éditeur

Sources : `src/furniture/panel.ts:171`, `src/furniture/panel.ts:327`.

Constat de code : les champs sont désactivés selon le verrouillage initial. Décocher Verrouiller ne réactive pas les dimensions/placement dans le brouillon. Il faut enregistrer puis rouvrir.

Correction : mettre à jour `disabled` sans recréer les contrôles ; préserver la transaction et Annuler.

### 10. P3 — Le départ en Visite peut refuser le vide d’un canapé en L

Sources : `src/scene/navigation.ts:56`, `src/furniture/layer.ts:239`.

Constat de code : les boîtes englobantes mondiales des maillages incluent le creux libre du L et les triangles vides autour d’un meuble tourné. Le contrôle du point de départ peut donc les considérer occupés.

Correction : tester les parties réellement occupées en coordonnées du meuble. Reproduction NullEngine dédiée encore à exécuter.

## UI, UX et fonctionnalités

- La séparation Maison/Meubles, l’éditeur en popup, les unités attachées et le schéma du canapé donnent une structure cohérente. Ajout, ouverture de l’éditeur, message d’erreur et Annuler ont été inspectés en production.
- En Plan, le nom de pièce peut recouvrir le meuble sélectionné et ses distances. Donner priorité visuelle à la sélection et éloigner son étiquette ; les distances sont très petites à cette échelle.
- Pour un premier usage, Importer ma maison mène uniquement à un JSON. Expliquer comment obtenir ce fichier et proposer un exemple de format aiderait davantage qu’un nouveau bouton principal.
- La démonstration vide illustre peu les possibilités. Un aménagement fictif facultatif permettrait de découvrir canapé, TV liée et édition sans toucher aux données personnelles.
- Lors d’un import portant un identifiant déjà présent, afficher ce qui sera remplacé et proposer un export préalable. Le remplacement actuel est documenté mais peu explicite dans le parcours.
- Après stabilisation, la comparaison de variantes d’aménagement et l’export d’une vue en plan seraient des fonctionnalités utiles à évaluer. Ce sont des propositions, pas des fonctionnalités existantes ni des travaux engagés.
