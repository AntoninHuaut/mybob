# Parcours de bout en bout — version actuelle

Demande : tester l’application actuelle et corriger les défauts rencontrés, sans consacrer cette passe à la compatibilité avec les anciennes versions. Base : `c05d6df`. Les parcours ci-dessous ont été exécutés dans le navigateur intégré, sur la démonstration fictive, puis sur son build de production local. Aucun aménagement personnel n’a été utilisé.

## Exécution réelle dans le navigateur

Formats contrôlés : 390 × 844, 320 × 568, paysage 568 × 320 et ordinateur 1280 × 720. Il s’agit de tailles de fenêtre simulées avec les interactions disponibles dans le navigateur de test, pas d’un appareil iOS/Android physique. Les gestes multitouch sont couverts séparément par les tests Babylon NullEngine.

## Corrections

1. **Navigation du Plan** : l’entrée Babylon d’origine accumulait une rotation malgré les angles verrouillés, et le pincement modifiait le rayon sans changer l’échelle orthographique. `HouseOrbitPointersInput` conserve les gestes 3D et route le glisser du Plan vers le déplacement, le pincement vers l’échelle bornée du Plan. Le test du moteur passe d’un déplacement nul et d’un span inchangé à un déplacement effectif et un span divisé par deux pour un écart des doigts doublé. Le rayon ne change plus pendant le pincement du Plan.
2. **Outils hors écran en paysage** : hauteur disponible bornée et défilement vertical sur les fenêtres basses ; les boutons conservent leur taille.
3. **Validation du nom inchangé** : la confirmation ferme le formulaire sans appeler le stockage.
4. **Développement local** : après une réoptimisation Vite, des shaders recevaient la page HTML en guise de source et les surfaces disparaissaient. L’exclusion cohérente de Babylon de la préoptimisation conserve un seul graphe de modules ; le rendu complet a été recontrôlé après rechargement. Le build compilé a également été inspecté et sa console ne contient pas d’erreur.

L’aide courte du Plan indique le glisser ; sur un pointeur tactile, les instructions affichent les gestes au lieu des raccourcis clavier. La marche en visite reste destinée au clavier ; aucun joystick tactile n’a été ajouté dans cette passe de stabilisation.

## Régressions automatisées et limites

Tests ajoutés : déplacement du Plan à 30/60/120 Hz ; routage de `onMultiTouch`, limites du zoom et invariance du rayon ; maintien des gestes perspective ; validation sans modification du nom. `pnpm run ci` a réussi avec Node 24 : 227 tests, formatage, TypeScript, build public et contrôle d’exclusion du plan personnel. Les tests géométriques ne remplacent pas les parcours visuels décrits plus haut.

Cette liste documente des parcours manuels réellement exécutés, pas une nouvelle suite Playwright automatisée. Aucun test de migration ancienne, Safari/iOS physique ou matériel Android n’est revendiqué.

Artefacts locaux ignorés : `artifacts/e2e-landscape.jpg`, `artifacts/e2e-mobile-export.png` et le script de reproduction `artifacts/probe-plan-input.ts`.
